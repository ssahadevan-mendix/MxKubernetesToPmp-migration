1. Overview

mx2pmp.py migrates Mendix applications from Mendix on Kubernetes, connected architecture (Mendix Operator in your cluster, environments managed from the Mendix Portal) to Private Mendix Platform (PMP) 2.8. It is a single Python 3.9+ file with no third-party packages. External tools used: kubectl, git, pg_dump/pg_restore, aws CLI.

The tool reads the source cluster directly (MendixApp custom resources, StorageInstances, Secrets), so it does not depend on the Portal or the Private Cloud API. It drives PMP through its REST API (deployservice/v1, buildservice/v1) using HTTP Basic auth with a PMP user and Personal Access Token.

3. Prerequisites and credentials

  • Python 3.9 or newer; kubectl, git, PostgreSQL client tools, AWS CLI on the PATH.
  • Read access to the source cluster (MendixApp CRs, StorageInstances, Secrets in the app namespaces).
  • A PMP service user with a Personal Access Token; the target Git provider registered in PMP.
  • Network reachability from the host running the tool to both databases and both object stores.

Credentials are passed through environment variables only:

KUBECONFIG / kube context             # read access to the SOURCE cluster
TEAMSERVER_PAT                        # Mendix PAT with Team Server read scope
TARGET_GIT_USER / TARGET_GIT_TOKEN    # push rights on the target Git provider
PMP_USER / PMP_PAT                    # PMP service user + Personal Access Token
SOURCE_DB_URL / TARGET_DB_URL         # postgres://user:pass@host:5432/db  (see db-url)
Secrets handlingNever put credentials in mx2pmp.json. export --include-secrets writes secret values to mx2pmp-work/export/... with file mode 0600; delete those files after the migration.

4. Workflow per application

# 1. Discover
python3 mx2pmp.py init                       # writes mx2pmp.json template
kubectl config use-context <source-cluster>
python3 mx2pmp.py inventory --add-to-config  # discovers MendixApp CRs, fills apps[]
#   edit mx2pmp.json: pmp.base_url, defaults.*, plan_map, mx_project_id per app

# 2. Export and plan
python3 mx2pmp.py export orders              # CR + StorageInstances + secret key names
python3 mx2pmp.py plan   orders              # PMP payloads in mx2pmp-work/plan/orders/*.json
#   review plan files; WARN lines list secrets, runtime version, memory, appUrl

# 3. Source code
python3 mx2pmp.py mirror-repo orders --dry-run && python3 mx2pmp.py mirror-repo orders
#   in PMP: create the app from the mirrored repo, copy its id into pmp_app_id

# 4. PMP environment and package
python3 mx2pmp.py pmp create-env   orders --mode Test --dry-run
python3 mx2pmp.py pmp create-env   orders --mode Test
python3 mx2pmp.py pmp apply-config orders --mode Test
python3 mx2pmp.py pmp build        orders --branch main --version 1.4.0
python3 mx2pmp.py pmp deploy       orders --mode Test          # deploy package
python3 mx2pmp.py pmp deploy       orders --mode Test --action Stop

# 5. Cut-over: stop the source environment in the Mendix Portal (or scale the CR to 0)
eval "$(python3 mx2pmp.py db-url source -n mx-apps --secret orders-test-database)"
eval "$(python3 mx2pmp.py db-url target -n mendix-apps --secret <pmp-env-db-secret> --context <pmp-cluster>)"
python3 mx2pmp.py migrate-db    orders --mode Test --execute --yes
python3 mx2pmp.py migrate-files orders --mode Test             # dry-run
python3 mx2pmp.py migrate-files orders --mode Test --execute
python3 mx2pmp.py pmp deploy    orders --mode Test --action Start
python3 mx2pmp.py validate      orders --mode Test
python3 mx2pmp.py report

Repeat for Acceptance and Production. State is kept in mx2pmp-work/state.json; every command is idempotent or guarded by --dry-run, --execute, --yes or --force.

6. Configuration notes

  • defaults.constants_mode: env emits one MX_<Module>_<Constant> variable per constant (Operator convention); runtime emits a single MicroflowConstants JSON runtime setting.
  • defaults.plan_map maps source Operator plan names to PMP storage and database plan names.
  • defaults.file_key_layout: flat when both storage plans keep objects under the same key; nested re-keys to aa/bb/<uuid> and writes a manifest.
  • Per-environment overrides: app_url, replicas, display_name, cluster_name, namespace, storage_plan, database_plan, core_resource_size, licenseId, licenseKey.
  • plan --overrides file.json replaces constant values, for example new endpoints on the PMP side.

A complete example is provided in mx2pmp.sample.json.

7. Caveats to verify in your environment

MendixApp CR field namesThey differ slightly across Mendix Operator versions. The exporter reads several aliases (appURL/appUrl, runtime.microflowConstants as JSON string or object). Check mx2pmp-work/export/<app>/<Mode>.json once and adjust build_plan() if a field is missed.
PMP REST responses are untypedId extraction and status polling use tolerant matching. If pmp build or deploy time out while the portal shows success, adjust the patterns in _status_of / _env_status_from_dashboard.
Runtime versionThe PMP build must use a base image that supports the source runtime version (shown as a WARN in plan).
Consistent data copyStop the source environment before migrate-db. The Mendix runtime performs schema synchronisation on the first Start in PMP; keep the source environment until validation passes.
Database scopemigrate-db is PostgreSQL only. For managed databases such as RDS, run the tool from a host that can reach both databases, or inside a kubectl run pod with the postgres client image.
